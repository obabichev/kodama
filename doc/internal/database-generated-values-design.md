# Database-Generated Values Architecture

## Problem Statement

Kodama needs to support various types of database-generated column values:

1. **Always generated by database** - SERIAL, IDENTITY, auto-increment columns
2. **Optionally generated by database** - DEFAULT values, timestamps
3. **Generated with expressions** - GENERATED columns (computed from other columns)
4. **Generated on specific events** - Trigger-based values, audit timestamps

Current INSERT generation requires all columns as parameters. We need a flexible architecture that:
- Excludes always-generated columns from INSERT
- Makes optionally-generated columns optional parameters
- Is extensible for future generation strategies
- Maintains compile-time type safety

## Phase 1 Scope (Version 0.3.0)

**Immediate implementation:** Auto-increment columns only (SERIAL and IDENTITY)

### What's Included in Phase 1
- ✅ **SERIAL types** - `serial()`, `bigserial()`, `smallserial()` - PostgreSQL-specific
- ✅ **IDENTITY modifier** - `.identity()` on integer types - SQL standard
- ✅ **AlwaysGenerated strategy** - Excludes columns from INSERT
- ✅ **Code generator** - Detects and excludes auto-increment columns

### What's NOT in Phase 1
- ❌ SqlExpression infrastructure (Phase 2+)
- ❌ DEFAULT values with optional parameters (Phase 2)
- ❌ GENERATED columns with computed expressions (Phase 3)
- ❌ `.alwaysGenerated()` for triggers (Phase 4)

**User API Examples for Phase 1:**
```kotlin
// PostgreSQL SERIAL
val id = serial("id").primaryKey()

// SQL Standard IDENTITY
val id = integer("id").identity().primaryKey()
val id = bigint("id").identity().primaryKey()
```

Both approaches exclude the `id` parameter from generated `insert()` methods.

## Core Concepts

### 1. Type-Safe SQL Expressions

SQL expressions for defaults and computed columns must be type-safe:

```kotlin
/**
 * Type-safe SQL expression that can be used in DEFAULT or GENERATED clauses
 * Type parameter T ensures expression matches column type
 */
sealed class SqlExpression<T> {
    abstract fun toSql(): String
}

/**
 * Literal value expression
 */
data class SqlLiteral<T>(val value: T) : SqlExpression<T>() {
    override fun toSql(): String = when (value) {
        is String -> "'$value'"
        is Number -> value.toString()
        is Boolean -> value.toString().uppercase()
        null -> "NULL"
        else -> throw IllegalArgumentException("Unsupported literal type: ${value::class}")
    }
}

/**
 * Function call expression (e.g., CURRENT_TIMESTAMP, NOW(), gen_random_uuid())
 */
data class SqlFunction<T>(val functionName: String) : SqlExpression<T>() {
    override fun toSql(): String = functionName
}

/**
 * Column reference (for GENERATED columns)
 */
data class SqlColumnRef<T>(val columnName: String) : SqlExpression<T>() {
    override fun toSql(): String = columnName
}

/**
 * Binary operation (for GENERATED columns like: price * 1.1)
 */
data class SqlBinaryOp<T>(
    val left: SqlExpression<*>,
    val operator: String,
    val right: SqlExpression<*>
) : SqlExpression<T>() {
    override fun toSql(): String = "${left.toSql()} $operator ${right.toSql()}"
}

/**
 * Raw SQL expression (escape hatch for complex cases)
 */
data class SqlRaw<T>(val sql: String) : SqlExpression<T>() {
    override fun toSql(): String = sql
}
```

**Predefined constants for common cases:**

```kotlin
object SqlDefaults {
    // Timestamp functions
    val CurrentTimestamp: SqlExpression<OffsetDateTime> = SqlFunction("CURRENT_TIMESTAMP")
    val Now: SqlExpression<OffsetDateTime> = SqlFunction("NOW()")
    val CurrentDate: SqlExpression<LocalDate> = SqlFunction("CURRENT_DATE")
    val CurrentTime: SqlExpression<LocalTime> = SqlFunction("CURRENT_TIME")

    // UUID generation
    val RandomUuid: SqlExpression<String> = SqlFunction("gen_random_uuid()")

    // Boolean defaults
    val True: SqlExpression<Boolean> = SqlLiteral(true)
    val False: SqlExpression<Boolean> = SqlLiteral(false)

    // Null
    fun <T> Null(): SqlExpression<T?> = SqlLiteral(null)
}

/**
 * Builder for creating expressions in GENERATED columns
 */
class SqlExpressionBuilder {
    fun <T> column(name: String): SqlExpression<T> = SqlColumnRef(name)
    fun <T> literal(value: T): SqlExpression<T> = SqlLiteral(value)

    // Arithmetic operators
    operator fun <T : Number> SqlExpression<T>.plus(other: SqlExpression<T>): SqlExpression<T> =
        SqlBinaryOp(this, "+", other)

    operator fun <T : Number> SqlExpression<T>.minus(other: SqlExpression<T>): SqlExpression<T> =
        SqlBinaryOp(this, "-", other)

    operator fun <T : Number> SqlExpression<T>.times(other: SqlExpression<T>): SqlExpression<T> =
        SqlBinaryOp(this, "*", other)

    operator fun <T : Number> SqlExpression<T>.div(other: SqlExpression<T>): SqlExpression<T> =
        SqlBinaryOp(this, "/", other)
}
```

### 2. Value Generation Strategy

A column's value generation strategy determines how INSERT handles it:

```kotlin
/**
 * Defines how a column's value is generated
 */
sealed interface GenerationStrategy {
    /**
     * Value is ALWAYS generated by database, NEVER provided by client
     * Examples: SERIAL, auto-increment
     * INSERT behavior: Column excluded from INSERT statement
     */
    object AlwaysGenerated : GenerationStrategy

    /**
     * Value CAN BE generated by database if not provided by client
     * Examples: DEFAULT values, CURRENT_TIMESTAMP
     * INSERT behavior: Optional parameter in insert() method
     */
    data class DefaultValue<T>(val expression: SqlExpression<T>) : GenerationStrategy

    /**
     * Value is COMPUTED by database from other columns
     * Examples: GENERATED ALWAYS AS (expression) STORED
     * INSERT behavior: Column excluded from INSERT statement
     */
    data class Computed<T>(val expression: SqlExpression<T>) : GenerationStrategy

    /**
     * Value MUST be provided by client
     * Examples: Regular columns
     * INSERT behavior: Required parameter in insert() method
     */
    object ClientProvided : GenerationStrategy
}
```

### 3. Column Enhancement

**ColumnType stays simple** - no generation strategy:

```kotlin
interface ColumnType<T> {
    val sqlType: String
    fun getValue(rs: ResultSet, columnName: String): T
}

// SERIAL types - just define SQL type
object SerialColumnType : ColumnType<Int> {
    override val sqlType = "SERIAL"
    override fun getValue(rs: ResultSet, columnName: String) = rs.getInt(columnName)
}

object IntColumnType : ColumnType<Int> {
    override val sqlType = "INTEGER"
    override fun getValue(rs: ResultSet, columnName: String) = rs.getInt(columnName)
}
```

**Column class tracks generation strategy:**

```kotlin
class Column<T>(
    val table: Table,
    val name: String,
    val type: ColumnType<T>,
    val nullable: Boolean = false,
    val generationStrategy: GenerationStrategy = GenerationStrategy.ClientProvided
)
```

### 4. Column Modifiers for Generation

Provide fluent API for specifying generation behavior:

```kotlin
// Extension functions on Column<T>

/**
 * Marks column as having a database DEFAULT value
 * Makes parameter optional in insert() method
 * Type-safe: expression type must match column type
 */
fun <T> Column<T>.defaultValue(expression: SqlExpression<T>): Column<T> {
    return Column(
        table, name, type, nullable,
        generationStrategy = GenerationStrategy.DefaultValue(expression)
    )
}

/**
 * Marks column as computed by database from other columns
 * Excludes from insert() method
 * Type-safe: expression type must match column type
 */
fun <T> Column<T>.generatedAs(block: SqlExpressionBuilder.() -> SqlExpression<T>): Column<T> {
    val expression = SqlExpressionBuilder().block()
    return Column(
        table, name, type, nullable,
        generationStrategy = GenerationStrategy.Computed(expression)
    )
}

/**
 * Marks column as GENERATED ALWAYS AS IDENTITY (SQL standard auto-increment)
 * Excludes from insert() method
 * Works with INTEGER, BIGINT, SMALLINT types
 */
fun <T : Number> Column<T>.identity(): Column<T> {
    return Column(
        table, name, type, nullable,
        generationStrategy = GenerationStrategy.AlwaysGenerated
    )
}

/**
 * Marks column value as always generated by database (triggers, sequences)
 * Excludes from insert() method
 */
fun <T> Column<T>.alwaysGenerated(): Column<T> {
    return Column(
        table, name, type, nullable,
        generationStrategy = GenerationStrategy.AlwaysGenerated
    )
}
```

## API Examples

### Example 1: SERIAL Primary Key (PostgreSQL-specific)

```kotlin
object Users : Table("users") {
    val id = serial("id").primaryKey()
    // SERIAL is PostgreSQL-specific auto-increment
    // SQL: id SERIAL PRIMARY KEY
    val name = varchar("name", 255)
    val email = varchar("email", 255)
}

// Generated insert - id excluded
fun Users.insert(
    transaction: JdbcTransaction,
    name: String,
    email: String
): InsertResult
```

### Example 2: IDENTITY Primary Key (SQL Standard)

```kotlin
object Products : Table("products") {
    val id = integer("id").identity().primaryKey()
    // IDENTITY is SQL standard auto-increment
    // SQL: id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY
    val name = varchar("name", 255)
    val price = decimal("price", 10, 2)
}

// Or with BIGINT for large IDs
object Orders : Table("orders") {
    val id = bigint("id").identity().primaryKey()
    // SQL: id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
    val userId = integer("user_id")
    val total = decimal("total", 10, 2)
}

// Generated insert - id excluded
fun Products.insert(
    transaction: JdbcTransaction,
    name: String,
    price: BigDecimal
): InsertResult
```

**SERIAL vs IDENTITY:**
- **SERIAL** - PostgreSQL-specific, creates implicit sequence, simpler syntax
- **IDENTITY** - SQL standard (SQL:2003), more control, portable to other databases
- Both excluded from INSERT parameters
- Use SERIAL for PostgreSQL-only projects, IDENTITY for portability

### Example 3: Default Values (Future)

```kotlin
import com.obabichev.kodama.schema.SqlDefaults

object Posts : Table("posts") {
    val id = serial("id").primaryKey()
    val title = varchar("title", 255)

    val isPublished = boolean("is_published").defaultValue(SqlDefaults.False)

// Generated insert - id excluded, status, createdAt, isPublished optional
fun Posts.insert(
    transaction: JdbcTransaction,

    status: String? = null,  // Optional - uses DEFAULT if null
    createdAt: OffsetDateTime? = null,  // Optional - uses DEFAULT if null
    isPublished: Boolean? = null  // Optional - uses DEFAULT if null
): InsertResult

// Usage:
Posts.insert(transaction, title = "Hello")  // Uses all defaults
Posts.insert(transaction, title = "Hello", status = "published")  // Override status
```

```kotlin
object Orders : Table("orders") {
```

## Implementation Phases

### Phase 1: Core Infrastructure (Immediate - 0.3.0)

**Goal:** Support auto-increment columns (SERIAL and IDENTITY)

1. Add `GenerationStrategy` sealed interface to `kodama-core`
2. Add `generationStrategy` property to `Column<T>` class (not ColumnType!)
3. **SERIAL Support (PostgreSQL-specific):**
   - Implement `SerialColumnType`, `BigSerialColumnType`, `SmallSerialColumnType`
   - Add `serial()`, `bigserial()`, `smallserial()` functions to `Table` DSL
   - These create columns with `AlwaysGenerated` strategy
4. **IDENTITY Support (SQL Standard):**
   - Add `.identity()` extension function on `Column<T : Number>`
   - Returns column with `AlwaysGenerated` strategy
   - Works with existing `integer()`, `bigint()`, `smallint()` types
5. Update code generator to:
   - Detect `serial()`, `bigserial()`, `smallserial()` calls (type-based)
   - Detect `.identity()` calls (modifier-based)
   - Mark both as `AlwaysGenerated`
   - Exclude `AlwaysGenerated` columns from insert parameters
   - Exclude `AlwaysGenerated` columns from INSERT statement

**Note:** Phase 1 does NOT implement SqlExpression - that's for future phases. Detection is simple string matching.

**Result:** Both SERIAL and IDENTITY auto-increment columns work without requiring INSERT parameters

### Phase 2: Default Values (Future - 0.4.0 or later)

**Goal:** Support optional parameters for DEFAULT values

1. Implement `SqlExpression<T>` sealed class hierarchy
2. Implement `SqlDefaults` object with predefined constants
3. Implement `DefaultValue<T>` strategy (with SqlExpression)
4. Add `.defaultValue(expression: SqlExpression<T>)` column modifier
5. Update code generator to:
   - Detect `.defaultValue(` calls
   - Make `DefaultValue` columns optional parameters (`Type? = null`)
   - Include column in INSERT only if value provided
   - Use SQL `DEFAULT` keyword when value is null

**Result:** Columns with defaults become optional in insert() with type-safe expressions

### Phase 3: Computed Columns (Future)

**Goal:** Support GENERATED columns

1. Implement `SqlExpressionBuilder` class with operator overloads
2. Implement `Computed<T>` strategy (with SqlExpression)
3. Add `.generatedAs(block: SqlExpressionBuilder.() -> SqlExpression<T>)` column modifier
4. Update code generator to:
   - Detect `.generatedAs(` or `.generatedAs {` calls
   - Exclude `Computed` columns from insert parameters
   - Exclude `Computed` columns from INSERT statement

**Result:** Computed columns automatically excluded with type-safe expression DSL

### Phase 4: Advanced Features (Future)

- Trigger-generated values (`.alwaysGenerated()` marker)
- IDENTITY columns (SQL standard auto-increment)
- UUID generation strategies
- Sequence-based generation

## Code Generator Logic

### Detection Algorithm

The code generator only needs to detect **which strategy** a column uses, not parse the actual SqlExpression. The expression itself is evaluated at runtime by Kodama core.

```kotlin
data class ColumnInfo(
    val name: String,
    val kotlinType: String,
    val generationStrategy: GenerationStrategyType,  // Simplified enum for codegen
    val nullable: Boolean
)

// Simplified enum for code generation - we don't need the actual SqlExpression
enum class GenerationStrategyType {
    ALWAYS_GENERATED,  // Exclude from INSERT
    DEFAULT_VALUE,     // Optional parameter
    COMPUTED,          // Exclude from INSERT
    CLIENT_PROVIDED    // Required parameter
}

fun detectGenerationStrategy(columnDefinition: String): GenerationStrategyType {
    return when {
        // Phase 1: Auto-increment (SERIAL and IDENTITY)
        columnDefinition.contains("serial(") ||
        columnDefinition.contains("bigserial(") ||
        columnDefinition.contains("smallserial(") ||
        columnDefinition.contains(".identity()") ->
            GenerationStrategyType.ALWAYS_GENERATED

        // Phase 2: Default values (just detect presence, don't parse expression)
        columnDefinition.contains(".defaultValue(") ->
            GenerationStrategyType.DEFAULT_VALUE

        // Phase 3: Computed columns (just detect presence, don't parse expression)
        columnDefinition.contains(".generatedAs(") ||
        columnDefinition.contains(".generatedAs {") ->
            GenerationStrategyType.COMPUTED

        // Phase 4: Explicit always-generated marker (for triggers, etc.)
        columnDefinition.contains(".alwaysGenerated()") ->
            GenerationStrategyType.ALWAYS_GENERATED

        // Default: client must provide
        else -> GenerationStrategyType.CLIENT_PROVIDED
    }
}
```

**Key insight:** Code generator doesn't need to parse SqlExpression objects. It only needs to know which category each column falls into to generate the correct method signature.

### INSERT Method Generation

```kotlin
fun generateInsertMethod(table: TableInfo, columns: List<ColumnInfo>) {
    // Separate columns by generation strategy
    val excluded = columns.filter {
        it.generationStrategy == GenerationStrategyType.ALWAYS_GENERATED ||
        it.generationStrategy == GenerationStrategyType.COMPUTED
    }

    val optional = columns.filter {
        it.generationStrategy == GenerationStrategyType.DEFAULT_VALUE
    }

    val required = columns.filter {
        it.generationStrategy == GenerationStrategyType.CLIENT_PROVIDED
    }

    // Generate method signature
    appendLine("fun ${table.name}.insert(")
    appendLine("    transaction: JdbcTransaction,")

    // Required parameters first
    required.forEach { col ->
        appendLine("    ${col.name}: ${col.kotlinType},")
    }

    // Optional parameters (with defaults) last
    optional.forEach { col ->
        val nullableType = if (col.nullable) col.kotlinType else "${col.kotlinType}?"
        appendLine("    ${col.name}: $nullableType = null,")
    }

    appendLine("): InsertResult {")

    // Generate column list (exclude ALWAYS_GENERATED and COMPUTED)
    appendLine("    val columns = mutableListOf<Column<*>>()")
    appendLine("    val values = mutableListOf<Any?>()")

    required.forEach { col ->
        appendLine("    columns.add(table.${col.name})")
        appendLine("    values.add(${col.name})")
    }

    optional.forEach { col ->
        appendLine("    if (${col.name} != null) {")
        appendLine("        columns.add(table.${col.name})")
        appendLine("        values.add(${col.name})")
        appendLine("    }")
    }

    appendLine("    val insert = InsertStatement(table, columns, values)")
    appendLine("    return transaction.executeInsert(insert)")
    appendLine("}")
}
```

## Migration Strategy

### Backward Compatibility

**Existing code continues to work:**

```kotlin
// Old way - still valid
object Users : Table("users") {
    val id = integer("id").primaryKey()  // Must provide ID manually
    val name = varchar("name", 255)
}

// Generated: Users.insert(transaction, id, name) - unchanged
```

**New code opts into auto-generation:**

```kotlin
// New way - opt-in
object Users : Table("users") {
    val id = serial("id").primaryKey()  // Change to serial
    val name = varchar("name", 255)
}

// Generated: Users.insert(transaction, name) - id excluded
```

### Gradual Adoption

Users can migrate table-by-table:

1. Change `integer("id")` to `serial("id")`
2. Regenerate code: `./gradlew generateKodamaExtensions`
3. Update insert calls (remove id parameter)
4. Retrieve generated IDs from `InsertResult.generatedKeys`

## Alternative Designs Considered

### Alternative 1: Annotation-Based

```kotlin
@AlwaysGenerated
val id = integer("id").primaryKey()
```

**Rejected:**
- Requires reflection or annotation processing
- Violates Kodama's "no reflection" principle
- Less type-safe

### Alternative 2: Separate Column Classes

```kotlin
class SerialColumn(...) : Column<Int>(...)
class DefaultColumn<T>(...) : Column<T>(...)
```

**Rejected:**
- More complex class hierarchy
- Harder to add strategies later
- Less flexible than property-based approach

### Alternative 3: Builder Pattern

```kotlin
val id = column("id") {
    type = IntColumnType
    generation = AlwaysGenerated
    primaryKey = true
}
```

**Rejected:**
- Verbose compared to current DSL
- Breaks existing API style
- More boilerplate for users

## Benefits of Proposed Design

1. **Extensible** - Easy to add new generation strategies
2. **Type-safe** - Compile-time checks for all strategies
3. **Backward compatible** - Existing code unchanged
4. **Opt-in** - Users choose when to use generation
5. **Flexible** - Supports both type-based and modifier-based specification
6. **No reflection** - All information available at compile time
7. **Intuitive API** - Matches PostgreSQL semantics

## Recommendation

Implement in phases:

- **Phase 1 (0.3.0):** SERIAL support only (AlwaysGenerated)
- **Phase 2 (0.4.0):** DEFAULT values (DefaultValue strategy)
- **Phase 3 (0.5.0):** GENERATED columns (Computed strategy)
- **Phase 4+:** Advanced features as needed

This provides immediate value while establishing architecture for future growth.
