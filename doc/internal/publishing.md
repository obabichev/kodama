# Publishing Kodama to Maven Central

This document describes the complete process for publishing Kodama releases to Maven Central.

## Prerequisites

### Sonatype Central Portal Account
- ✅ Account created at https://central.sonatype.com/
- ✅ Namespace `com.obabichev` verified
- ✅ Login with Google OAuth

### GPG Key Configuration
- ✅ GPG key exists and is configured
- ✅ Key published to keyservers

### Credentials Configuration

File: `~/.gradle/gradle.properties`
```properties
signing.keyId=YOUR_GPG_KEY_ID
mavenCentralUsername=YOUR_CENTRAL_PORTAL_TOKEN
mavenCentralPassword=YOUR_CENTRAL_PORTAL_PASSWORD
```

**Note:** Credentials must be generated from https://central.sonatype.com/ (View Account → Generate User Token).

## Published Artifacts

When publishing, three packages are uploaded to Maven Central:

### 1. kodama-core
- **Artifact ID**: `com.obabichev.kodama:kodama-core`
- **Purpose**: Core library with query builder API, table definitions, column types
- **Usage**:
  ```kotlin
  dependencies {
      implementation("com.obabichev.kodama:kodama-core:0.4.0")
  }
  ```

### 2. kodama-compiler-plugin
- **Artifact ID**: `com.obabichev.kodama:kodama-compiler-plugin`
- **Purpose**: Gradle plugin implementation containing the code generator
- **Usage**: Automatically included via plugin marker

### 3. com.obabichev.kodama.gradle.plugin
- **Artifact ID**: `com.obabichev.kodama:com.obabichev.kodama.gradle.plugin`
- **Purpose**: Plugin marker (auto-generated by `java-gradle-plugin`)
- **Usage**: Enables modern plugin syntax:
  ```kotlin
  plugins {
      id("com.obabichev.kodama") version "0.4.0"
  }
  ```

All three are required and are automatically included in the release bundle.

## Release Process

### Step 1: Update Version

Update the version in `gradle.properties`:
```properties
version=0.3.1
```

### Step 2: Create Release Bundle

There are two Gradle tasks available:

#### Option A: createCentralBundle (Recommended)

Uses already-signed artifacts from Maven Local. This approach separates GPG signing from bundle creation.

```bash
# 1. Publish to Maven Local (requires GPG passphrase once)
./gradlew publishAllToMavenLocal

# 2. Create the bundle (no GPG required, can run multiple times)
./gradlew createCentralBundle
```

**Output**: `build/distributions/kodama-<version>-bundle.zip`

**Advantages:**
- Only enter GPG passphrase once
- Can regenerate bundle multiple times without re-signing
- Faster for iteration

#### Option B: createReleaseBundle

Publishes directly to staging directory and creates bundle in one step.

```bash
./gradlew createReleaseBundle
```

**Output**: `build/distributions/kodama-<version>-release.zip`

**Advantages:**
- Single command
- Doesn't use Maven Local repository

**Disadvantages:**
- Requires GPG passphrase every time
- Slower if you need to regenerate

### Step 3: Upload to Maven Central

1. Go to https://central.sonatype.com/
2. Click "Publish Component" button
3. Upload the generated ZIP file
4. Wait for validation (usually instant)
5. Review the artifacts
6. Click "Publish" button

The artifacts will be available on Maven Central within 15-30 minutes.

### Step 4: Verify Publication

Check that the new version is available:
- https://central.sonatype.com/artifact/com.obabichev.kodama/kodama-core
- https://repo1.maven.org/maven2/com/obabichev/kodama/

## Bundle Contents

The release bundle contains all required artifacts for Maven Central:

### Files per Module (x3 modules)
- `*.jar` - Main JAR
- `*-sources.jar` - Sources JAR (required)
- `*-javadoc.jar` - Javadoc JAR (required, can be empty)
- `*.pom` - POM file with complete metadata
- `*.module` - Gradle module metadata
- `*.asc` - GPG signatures for all files
- `*.md5` - MD5 checksums for all files
- `*.sha1` - SHA1 checksums for all files

### Total Files
- **87 files** for version 0.4.0 (includes all 3 modules with all artifacts and checksums)

## Project Configuration

Both modules are configured with:

- `maven-publish` plugin
- `signing` plugin with `useGpgCmd()`
- Complete POM metadata:
  - Name, description, URL
  - Apache 2.0 license
  - Developer information
  - SCM (GitHub) information
- Sources JAR task
- Javadoc JAR task (empty, acceptable for Maven Central)

### GPG Signing

- Uses `useGpgCmd()` - invokes system GPG
- GPG agent (`pinentry-mac`) shows GUI dialog for passphrase
- Passphrase cached by GPG agent (1-2 hours by default)
- No passphrase stored in gradle.properties

## Troubleshooting

### GPG "Operation cancelled" Error

If you see `gpg: signing failed: Operation cancelled`:

1. Make sure GPG agent is running:
   ```bash
   gpgconf --launch gpg-agent
   ```

2. Test GPG signing:
   ```bash
   echo "test" | gpg --clearsign
   ```

3. If using pinentry-mac, ensure it's configured:
   ```bash
   echo "pinentry-program /opt/homebrew/bin/pinentry-mac" >> ~/.gnupg/gpg-agent.conf
   gpgconf --kill gpg-agent
   gpgconf --launch gpg-agent
   ```

### "Artifacts not found" Error

For `createCentralBundle`, if you get "Artifacts not found in Maven Local repository":

```bash
./gradlew publishAllToMavenLocal
```

Then retry:
```bash
./gradlew createCentralBundle
```

### Bundle Validation Errors

If Maven Central rejects the bundle during upload:

- **Missing checksums**: Verify all .jar, .pom, .module, .asc files have .md5 and .sha1 files
- **Missing metadata**: Check POM files have name, description, url, licenses, developers, scm (already configured)
- **Missing signatures**: Ensure all JARs are signed with .asc files present
- **Invalid POM**: Verify POM XML is well-formed

### Credentials Error

If credentials don't work:

1. Generate new tokens from Central Portal:
   - Go to https://central.sonatype.com/
   - Click your username → "View Account"
   - Click "Generate User Token"
   - Copy username and password

2. Update `~/.gradle/gradle.properties`:
   ```properties
   mavenCentralUsername=<NEW_TOKEN_USERNAME>
   mavenCentralPassword=<NEW_TOKEN_PASSWORD>
   ```

**Note:** Old OSSRH tokens don't work with Central Portal. Must generate new tokens.

## Clean Release Build

For a completely clean release:

```bash
./gradlew clean
./gradlew publishAllToMavenLocal
./gradlew createCentralBundle
```

## File Locations

### createCentralBundle outputs:
- Bundle: `build/distributions/kodama-<version>-bundle.zip`
- Extracted files: `build/central-bundle/` (can be deleted after bundle creation)

### createReleaseBundle outputs:
- Bundle: `build/distributions/kodama-<version>-release.zip`
- Staging directory: `build/maven-staging/` (can be deleted after bundle creation)
- Extracted files: `build/release-bundle/` (can be deleted after bundle creation)

## Verification After Publishing

### Check Maven Local Artifacts

```bash
# List artifacts
ls -lh ~/.m2/repository/com/obabichev/kodama/kodama-core/0.4.0/

# Verify GPG signature
gpg --verify ~/.m2/repository/com/obabichev/kodama/kodama-core/0.4.0/kodama-core-0.4.0.pom.asc \
              ~/.m2/repository/com/obabichev/kodama/kodama-core/0.4.0/kodama-core-0.4.0.pom
```

### Check Bundle Contents

```bash
unzip -l build/distributions/kodama-0.4.0-bundle.zip
```

Expected: 87 files for 3 modules with all required artifacts and checksums.

## Security Notes

- `~/.gradle/gradle.properties` contains sensitive credentials
- Keep this file secure (not in version control)
- Recommended file permissions: `chmod 600 ~/.gradle/gradle.properties`
- GPG private key stays in `~/.gnupg/` (never committed)

## Central Portal Migration Notes

**OSSRH was shut down on June 30, 2025.** This project now uses Maven Central's new system:

- **Current approach**: Manual bundle upload via Central Portal web UI
- **Central Portal**: https://central.sonatype.com/
- **Publishing endpoint**: Not used (manual upload only)
- **Old OSSRH endpoint** (no longer works): `https://s01.oss.sonatype.org/`

The manual bundle upload approach is:
- More reliable
- Doesn't require API authentication issues
- Works perfectly with Google OAuth login
- Recommended by Sonatype for new projects
